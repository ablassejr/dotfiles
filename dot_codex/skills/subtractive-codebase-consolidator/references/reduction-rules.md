# Reduction rules

Investigate unnecessary obligations first, then duplicate authority, parallel mechanisms, unjustified boundaries, redundant representations, dependent residue, and local expression. Higher-level changes can make lower-level machinery unnecessary without adding a replacement abstraction.

Retirement changes what the system promises. It requires the user's authorization for that semantic change. Consolidation keeps the promise and reduces the mechanisms that satisfy it. Re-expression preserves the implementation's role and needs a concrete clarity or maintenance benefit. Do not bundle these changes under an ambiguous cleanup label.

Two pieces of code are consolidation candidates only after comparing inputs, outputs, errors, effects, ordering, consumers, performance obligations, environments, and reasons to change. A boundary can still protect trust, dependency direction, deployment independence, or compatibility when it has a single implementation. A canonical owner can have derived caches, replicas, and distinct transport representations without becoming duplicate authority.

When an abstraction mixes unrelated cases, it may be simpler to return the behavior to its callers, remove each caller's impossible cases, and share only the remaining common obligation. The target description should explain the resulting behavior and failure paths before code is changed.

The removal closure includes anything that becomes unnecessary because of the candidate: wrappers, mirrored mappings, configuration, flags, tests for retired behavior, fixtures, dependencies, and build steps. Every member needs justification. The planner deduplicates overlap; it does not prove reachability or compute semantic equivalence. Use existing analyzers and inspect their root models for those questions.

Report maintained source additions A, removals R, and the independent stock change. The default directional target is 5R >= 6A. It is a user policy from the supplied recommendation, not an empirical law or proof of correctness. Consider a coherent bounded campaign, reporting each patch; migration or characterization additions remain visible until their associated removal occurs.

The counter includes production, tests, tooling, and executable configuration under one fixed classification policy. All identical maintained copies count. Exact byte-identical moves receive zero addition and removal credit. cloc handles comments and blank lines; the reviewer still checks minification, rewrites that hide complexity, classification omissions, generated substitutions, unrelated deletion, and weakened tests. A source counter cannot establish those semantic properties.

A numerical exception names the actual patch, human authorization source, reason, expiration, and the specific waived invariant. A ratio waiver does not waive net growth. Neither waiver changes any preservation, coverage, execution, safety, or evidence requirement. A stable healthy domain does not have to shrink indefinitely.
