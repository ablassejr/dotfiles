# Local execution boundary

Snapshot creation reads the original and writes only to a separate run directory. Audit and planning do not execute repository code. A reviewable file-classification policy controls what can enter a runnable snapshot. Explicitly exclude credentials, tokens, private runtime state, and material outside the authorized analysis scope. The tool does not inspect secrets to decide whether they are secrets.

An experiment starts only when an authorization record identifies the baseline, allowed paths, actual authorization source, and expiration. The helper creates a new candidate directory and refuses to overwrite an existing one. The assistant can then edit that copy within the user's existing permission. Original repository content and Git metadata are compared before and after relevant operations. The tool reports a changed original; it never restores or deletes user data to make the comparison pass.

The execution runner sends regular-file inputs to an explicitly selected local Docker socket. The container has no host mounts, no host credentials in its environment, no Docker socket, no network interface beyond its isolated loopback, no added capabilities, and no permission escalation. Its root filesystem is read-only. Source and scratch files occupy a 512 MiB temporary filesystem. Memory is limited to 1 GiB with matching swap, CPU allocation to two, and process count to 128. Output is limited to 8 MiB and the configured deadline applies to each command.

The container image must already exist locally and is addressed by its immutable image ID and explicit platform. Pulling is disabled. It needs Python 3 and a full Perl standard library; repository-specific tools and dependencies must already be present. The runner overrides the image entrypoint and clears the image environment before launching the declared command. It inspects image-defined volumes and masks each with an empty read-only temporary filesystem; a volume that overlaps a required execution path is rejected. Use a trusted tool image without embedded secrets or privileged platform configuration. The local Docker daemon and its host remain part of the trust boundary.

The cloc Perl script and any explicitly configured local Perl libraries are copied into the temporary input stream and hashed. They are not bundled, downloaded, or installed by this package. Nothing from the caller's Docker configuration is used; the CLI receives an empty temporary configuration and a local Unix socket. The runner removes only its uniquely named container on interruption. If cleanup cannot complete, it reports that exact name instead of pruning unrelated containers. Attempt records identify the container, masked volume paths, and lifecycle state. Command logs flush while the command is running.

If the runtime or containment is unavailable, static inventory and planning remain useful. Dynamic verification is INCOMPLETE; do not run the checks directly on the host as a fallback. A container is a practical process boundary, not a guarantee against a compromised host or kernel. The caller supplies and trusts the local runtime.

Tool execution is local, but model inference is outside these scripts. This Codex session uses hosted inference. Fully offline use requires a separately configured local model and local embeddings and must avoid hosted connectors. Reports use local Markdown and JSON without remote assets or publishing.
