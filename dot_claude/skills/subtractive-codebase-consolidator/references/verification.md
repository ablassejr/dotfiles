# Verification evidence

When verification starts, the helper reloads the preserved basis, classifications, original digest, baseline digest, candidate digest, check definitions, runtime, and counter hash. It requires end-to-end coverage for the preserved obligations and integration coverage for each declared seam. Unknown consumers and skipped declared scope remain gaps. Check names alone do not establish coverage; the independent reviewer assesses the tests against the behavior.

The helper executes the same declared checks on fresh disposable copies of the baseline and candidate. Each check has an explicit tool-version command. Actual argument arrays, exit status, snapshot, rule hash, immutable image, output file, and output hash are retained. The source snapshots cannot be modified by the container. Baseline failures remain failures, and a passing candidate does not erase them.

The counter then measures both maintained inventories and their diff. Every maintained file must appear in the counter output; unknown languages and files omitted by the counter leave the result incomplete. Both identical files count. Byte-identical moves are removed from the churn comparison after their stock counts are recorded. A difference in names alone receives no removal credit. File counts, category counts, total stock, additions, removals, net change, and the 6:5 arithmetic must reconcile.

The first phase records INCOMPLETE while waiting for independent review, or FAILED when checks failed. This is deliberate: review needs the actual evidence produced by the run. Give a fresh reviewer the retained behavior, affected consumers, both snapshots or the patch, and the recorded logs. Ask for specific lost behavior, compatibility changes, weaker tests, unsupported assumptions, or hidden complexity. The review states the structural improvement, the anti-gaming assessment, concrete counterexamples, and unresolved questions. It binds to both the patch hash and the collected evidence hash.

Finalization revalidates the complete typed record. It checks the current snapshots, policy, helper implementation, tool hash, check definitions, receipt scope, command arguments, logs, and arithmetic. It reconstructs measurements from actual counter logs. A ratio exception can waive only the ratio, and a separate net-growth waiver is required for a positive net stock change. No exception waives missing measurements, failed checks, stale evidence, unknown consumers, unapproved scope, or review gaps.

The final states are VERIFIED, VERIFIED_WITH_EXCEPTIONS, INCOMPLETE, and FAILED. Exit codes are zero for the first two, two for incomplete input/evidence, and one for a failed check or policy. Verification is a bounded evidence statement and grants no permission to apply a patch, change the original, publish, or retire additional behavior.

These are local receipts, not signed attestations. Hashes detect drift and inconsistent records. A malicious owner who can rewrite code, snapshots, logs, and every hash can forge a local bundle; no cryptographic provenance claim is made. The collector obtains real process results during normal operation rather than accepting a supplied PASS string.

Tests target observable command behavior, persisted records, code counts, and sandbox effects. Existing tests of private structure should be replaced only within the request's scope, preserving their intended behavior coverage. Differential, generated, stateful, concurrency, failure, and mutation evidence are selected according to the actual contracts; no universal line or mutation threshold is invented.
