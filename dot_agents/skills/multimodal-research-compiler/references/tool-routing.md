# Tool routing

Route work by the fact that must be established. Tool output is retrieval context until verified against the underlying source.

- Use CodeGraph for symbols, call paths, imports, dependency topology, write surfaces, and blast radius. It does not prove rationale.
- Use Claude Context for conceptually related code, tests, internal documentation, and terminology that exact traversal can miss. Verify retrieved passages in current files.
- Use Git for introduction, movement, modification, deletion, and reintroduction. Chronology alone does not prove causation.
- Use GitHub for pull-request intent, review discussion, requested changes, linked issues, checks, reverts, and replacement work.
- Use Linear for current work intent, ownership, milestones, related issues, native dependencies, discussion, and recorded human decisions.
- Use Notion for approved goals, requirements, invariants, decisions, accepted risk, and release boundaries. Prefer an approved release or stable record set when precision matters.
- Use Docs MCP Server for applicable official CLI, API, protocol, platform, deprecation, and migration documentation. Fetch it before invoking a CLI.
- Use external search for primary prior art, research papers, current facts, and alternatives that local or official sources do not answer. Do not replace exact-version official documentation with a blog.
- Use file and media tools for supplied reports, transcripts, PDFs, spreadsheets, images, and architecture artifacts. Preserve user-specified source boundaries.

If the preferred capability is unavailable, use a fallback only when it can establish the same claim. Otherwise record the gap and its consequence. Never claim that a source was checked when only a search summary or secondary reference was available.
