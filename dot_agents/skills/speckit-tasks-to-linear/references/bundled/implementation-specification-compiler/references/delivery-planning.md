# Delivery planning

The plan translates an approved specification into independently useful work for the actual team. It identifies the source revision, intended outcome, responsible people when known, task boundaries, dependencies, and how each outcome will be observed. A tracker, repository work list, or portable plan can hold these records.

Partition by responsibility and mergeability. Split an oversized task when its outcomes can be reviewed independently. Keep necessary shared prerequisites and explain cross-owner handoffs. Do not create a fixed number of workstreams, equal issue counts, placeholder people, a new project for every lane, or a label absent from the project's convention. Apply explicit staffing and sizing constraints from the request.

For each task, explain the bounded outcome and its observable verification. Keep approved constraints and semantic source identity. Record ownership, dependencies, and PR boundaries in the selected planning structure. Unresolved estimates and owners remain unresolved; only a material choice that prevents a coherent plan needs a user question. Existing code-mass policies retain their actual scope.

Use the provider's native relationships when available. If it cannot represent a required relation, preserve the graph in its owning plan with stable task references and explain that execution must consult it. Validate direction, cycles, missing targets, and live readiness where accessible. A plan can show future parallel work without claiming simultaneous starts or live completion.

When publishing, create only the approved provider containers. Retain returned identifiers, then connect relationships and verify the fetched graph and content. Reconcile partial writes before retrying. Prepare and expose required review material through the selected shared document home; the issue tracker does not also need to store every artifact.

The [three-person Linear profile](three-person-workstreams.md) is a supported specialized automation contract. It applies only when that staffing and provider setup is selected. Its schemas are not the generic plan format.
